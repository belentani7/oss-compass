# Contribuir a OSS Compass

Gracias por contribuir. Antes de abrir un pull request, crea un entorno virtual, instala `.[test]` y ejecuta `pytest`. Las nuevas reglas deben ser pequeñas, deterministas cuando sea posible y acompañarse de pruebas.

Para cambios en el protocolo, describe el contrato de entrada, el código PVC, el impacto sobre la reproducibilidad y la compatibilidad. Para cambios en la confirmación distribuida, incluye casos con cero, una, dos y tres aprobaciones.

Los pull requests deben explicar qué problema resuelven, incluir documentación cuando cambie la API y evitar dependencias innecesarias. Las discusiones técnicas deben mantenerse en issues o pull requests para que el contexto sea público y reutilizable.
